# Charged Cartan Monte Carlo — v0.1 design: charge labels + annihilation / pairCreate moves

> **Status**: implemented (opt-in via `cfg.featureCharges` and the `feature*OnAnnihilate` flags)
> **Builds on**: [interaction-history Monte Carlo (earlier work)](../../interaction_history_monte_carlo.md)
> **Experiments**: [Experiment 01](../experiments/01-v0.1-BplusIII-comparison.md) — B + iii (deactivate + photon) comparison
> **Successor**: [v0.2 design](v0.2.md) — qudit-basis vertices

Living design note for the construction that succeeds the
"InteractionSimulation" line documented in
[../../interaction_history_monte_carlo.md](../../interaction_history_monte_carlo.md).
v0.1 captures the structural changes agreed during the design
discussion that followed the diverging-`D_S` finding in the
Cartan/local-frame model.

## Summary of the change vs the prior model

The prior model (1-qubit vertices on a Poisson-Delaunay initial layer,
Schwinger two-site `U` for interactions, Cartan/local-frame edge MIs,
relaxed eligibility) showed unbounded `D_S(σ)` growth at all `β` —
diagnosed as a heat-kernel artifact of (a) the ε-floored cross-worldline
edges being driven to MI = 0 by separable inputs and (b) the relaxed
eligibility creating small-world graphs.

v0.1 keeps the Cartan/local-frame edge structure but adds a discrete
charge degree of freedom and the corresponding move set so the frontier
is self-regulated by particle/antiparticle dynamics rather than
unbounded growth.

## Vertices

Each vertex `v` carries:

- a **one-qubit state** `ρ_v ∈ Eigen::Matrix2cd`, evolved as before;
- a **charge** `q_v ∈ [−1, +1]` (real, continuous). Discrete values
  `±1` and `0` are the special cases used by initial layer / neutral
  products; pair-creation can produce non-integer charges.

The state and the charge are *independent* registers — `U` acts on
states, charges are bookkeeping. The charge is a separate quantum
number, conserved by `U` in the same sense the Schwinger fermion-number
is a U(1) charge: it commutes with the interaction, and we track it
classically.

## Interaction unitary `U`

`U` is a configurable 4×4 two-qubit unitary. Two defaults:

- **Cartan-entangler**: a canonical fixed entangler
  `exp(i(c_x XX + c_y YY + c_z ZZ))` with `(c_x, c_y, c_z)` set by
  config. Most parsimonious; isolates the entangling content.
- **Schwinger two-site**: the current
  `(1/4a)(XX + YY) + (m/2)(−Z⊗I + I⊗Z)` Hamiltonian's exponential —
  available as a comparator so we don't lose the Schwinger connection.

The Schwinger construction is no longer *load-bearing*; v0.1 is honest
about being "a discrete graph of MI-coupled qubits with U(1) charge
conservation," not a faithful simulation of the Schwinger model.

## Initial layer

- `N` independent one-qubit random mixed states `ρ_v = M M† / Tr(M M†)`
  with `M` a 2×2 complex Gaussian (no inter-vertex MI; same as current).
- Charges assigned by mode (`cfg.initialChargeMode`):
  - `ALTERNATING` (default): even-index vertices `+1`, odd-index `−1`.
    Exactly `Q = 0`.
  - `RANDOM`: each vertex independently `±1` with equal probability.
    `Q ≈ 0` with √N fluctuations.

Delaunay edges are still drawn (for compatibility with the spatial
position machinery) but their MI is the ε-floor (separable inputs).

## Move set

Four moves, replacing the prior interact / un-interact pair:

1. **`interact`** — same-sign bowtie (or with-neutral).
   Eligibility: pick a random pair `(x, y)` of frontier vertices with
   `q_x · q_y ≥ 0` (same-sign or at least one neutral). Standard Regge
   action contribution.
   Product charges: `chargeOf_[U_A] = chargeOf_[A]`,
   `chargeOf_[V_B] = chargeOf_[B]`, `chargeOf_[Σ_AB] = 0`.

2. **`unInteract`** — deep cascade (unchanged from current).

3. **`annihilate`** — partial annihilation, no Regge change.
   Eligibility: pick a random `(+, −)` frontier pair `(p, m)` with
   `q_p > 0`, `q_m < 0`.
   Rule (charge-only, no vertex deletion — the *charges* annihilate
   but the *worldlines* persist as neutral systems):
   - If `q_p + q_m > 0`: neutralise `m` (`q_m → 0`), update `p`'s charge
     to `q_p + q_m`.
   - If `q_p + q_m < 0`: neutralise `p` (`q_p → 0`), update `m`'s charge
     to `q_p + q_m < 0`.
   - If `|q_p + q_m| < ε`: both become neutral.
   Total *signed* charge `Σ q_i` is exactly conserved.
   Total *baryon number* (count of `+` minus count of `−`) can change
   by ±1 per partial-annihilation event (a vertex's sign-bucket
   membership shifts when its charge transitions through zero).

   *Why charge-only and not vertex-deletion*: a vertex that has been a
   product of an interaction is referenced from the cell's vertex list.
   Deleting it from the spacetime would invalidate the cell. By
   neutralising the charge but keeping the vertex alive, the geometry
   stays consistent — only the U(1) quantum number changes. This also
   matches the QED picture more cleanly: in `e⁻e⁺ → γγ` the worldlines
   don't vanish, the *charge content* does (the worldlines continue as
   photon worldlines).

4. **`pairCreate`** — spontaneous pair-creation, no Regge change.
   Spawn two vertices `(p, m)` on the frontier with:
   - charges `q_p = 0.5 + δ`, `q_m = −0.5 + δ` where
     `δ ∈ [−ε_CP, +ε_CP]` is drawn uniformly. `ε_CP` is the
     CP-violation bias (config: `cfg.cpBias`, signed double, default 0).
     - Positive `ε_CP` favours net `+` content; negative favours `−`.
     - At `ε_CP = 0` the pair-creation is exactly C/CP-symmetric.
   - joint state: a fixed Bell state |Φ⁺⟩ = (|00⟩ + |11⟩)/√2 stored in
     `jointOf_[(p, m)]`. Bell state is reproducible and maximally
     entangled.
   - one-qubit marginals on each vertex: `Tr_other |Φ⁺⟩⟨Φ⁺| = I/2`
     (maximally mixed) — `S(ρ) = ln 2`, populates worldline-self MI.

`sweep()` proposes the four move types with equal weight by default
(configurable); the per-move acceptance handles balance.

## Sakharov diagnostic

With the partial-annihilation + CP-bias setup, all three Sakharov
conditions for baryogenesis are present:

| Condition | How it's met |
|---|---|
| (i) Baryon-number violation | Partial annihilation can change `N_+ − N_−` by ±1 per event |
| (ii) C / CP violation | Non-zero `ε_CP` biases pair-creation toward + or − |
| (iii) Out-of-equilibrium | Growth phase (`tune()`) is far-from-equilibrium; sweep approaches equilibrium |

The model can produce a net baryon excess from a Q=0 initial state if
`ε_CP ≠ 0` and the system departs from equilibrium long enough.

## Observables

Beyond the existing `D_S(σ)`:

- **`getGlobalCharge()`**: `Σ_v q_v` over the entire complex. At
  `ε_CP = 0` it's exactly conserved; at `ε_CP ≠ 0` it drifts as a
  measure of cumulative CP-violation.
- **`getChargeProfile()`**: per-time-slice `(N_+, N_−, N_0,
  Σq | ε_CP > 0)`. Shows whether charge clusters in time.
- **`getChargeCorrelation(maxDist)`**: `⟨q_v · q_w⟩` as a function of
  graph-distance `d(v, w)` for `d ≤ maxDist`. Positive correlation at
  short distance = same-charge clustering.
- **`getModuleCharges()`**: after a (Louvain / spectral) module
  decomposition of the MI-weighted graph, the per-module net charge.
  Reveals matter-dominant vs antimatter-dominant regions. *Note*:
  reaching per-module equilibrium will likely take substantial tuning
  — the dynamics has to keep modules stable long enough for their
  charge content to settle.
- **`getAnnihilationCount()` / `getPairCreateCount()`**: cumulative
  rates of the new moves.

## Configurable parameters

Numeric parameters (non-experimental):

```
cfg.beta                 — inverse temperature
cfg.epsilonI             — MI floor for zero edges
cfg.targetInteractions   — T-cap
cfg.cpBias               — CP-violation bias (signed double, default 0)
cfg.initialChargeMode    — ALTERNATING / RANDOM (only if charges enabled)
cfg.unitaryMode          — CARTAN_ENTANGLER / SCHWINGER  (deferred)
cfg.cartanCore           — (c_x, c_y, c_z) for the entangler
```

### Feature flags

Experimental features are toggled by boolean flags on `InteractionConfig`,
all named `featureXxx` (camelCase, matching the rest of the API) and all
defaulting to `false`. New experimental behaviour is *always* gated
behind a flag so old runs are bit-for-bit reproducible. A typical script
enables several at once:

```python
cfg = q.InteractionConfig()
cfg.featureCharges                 = True   # v0.1 — charge labels enabled
cfg.featureDeactivateOnAnnihilate  = True   # v0.1.B — annihilation removes from frontier
cfg.featurePhotonOnAnnihilate      = True   # v0.1.iii — spawn photon vertex on annihilation
```

Each experiment writeup should record the flag configuration it used at
the top of the results section.

Current flags:

| Flag | Effect |
|---|---|
| `featureCharges` | v0.1 charged Cartan: charge labels, annihilate / pairCreate moves, charge observables. |
| `featureDeactivateOnAnnihilate` | annihilate removes vertices from the frontier (worldlines terminate) instead of just neutralising their charges. Requires `featureCharges`. |
| `featurePhotonOnAnnihilate` | annihilate also spawns a new neutral "photon" vertex on the frontier, carrying the released information. Requires `featureCharges`. |
| `featureQuditBasis` *(deferred to v0.2)* | each vertex carries a 4-dim qudit state with charge intrinsic via Q̂. Removes the need for `featureCharges` (and the v0.1 limitations). |

The legacy `cfg.useCharges` flag is preserved as an alias for
`cfg.featureCharges` — setting either enables the charged-Cartan code
paths. Dependent flags are auto-cleared when `featureCharges` is off,
so a partially-configured run can't enter an undefined state.

## What v0.1 does NOT include (deferred to v0.2+)

- **4-dim qudit basis** — see "v0.2 sketch" below.
- **Explicit photon vertex** on annihilation events to restore energy
  bookkeeping (currently energy is non-conserved by the partial-
  annihilation move).
- **Cosmological constant `Λ_0`** as an independent parameter — frontier
  self-regulation via annihilation removes the need for it in v0.1, but
  having it back as a tuning dial could expose a wider phase diagram.
- **Face-glue moves** — discussed and held in reserve. May become
  unnecessary if charge clustering provides the inter-cell coupling we
  were after.
- **Tunable Cartan core scan** as an experiment — scan `(c_x, c_y, c_z)`
  to find which entangling structures support 4D emergence.

## Initial v0.1 β-scan results (cpBias = 0)

Same scan parameters as the chargeless-v2 scatter for direct
comparison: N=8, T=3000, 22 β log-spaced in [10⁻⁴, 5×10⁻³], 10 seeds
per β, K=15, σ-grid extended to 10¹⁰.

Per-β mean ± std peak D_S, with σ-saturation count in parentheses:

```
        β    |    v0.1 (charges on)       |    v2 (chargeless)
   1.0e-4   |  198.19 ± 103.49 (0/10)    |    0.07 ±  0.01 (0/10)
   3.06e-4  |  280.21 ± 100.81 (0/10)    |    0.38 ±  0.36 (0/10)
   1.00e-3  |     ~245    (range)        |    0.96 ±  0.15 (5/10)
   1.635e-3 |  216.07 ±  98.32 (0/10)    |    3.73 ±  0.54 (10/10)
   3.45e-3  |  272.76 ± 113.11 (0/10)    |   10.80 ±  1.85 (10/10)
   5.00e-3  |  250.75 ±  79.05 (0/10)    |   10.22 ±  2.27 (10/10)
```

**Three findings:**

1. **All phase structure collapses.** The v2 scan had clean
   zero-D / extended-D / high-D phases at different β. v0.1 has a
   single flat regime: peak D_S ≈ 250 ± 100 at every β value. The
   charge dynamics (annihilate / pairCreate) equilibrate so quickly
   that they wash out the action's ability to select different
   geometries.

2. **No σ-saturation anywhere.** Where v2 had all-saturated readings
   at high β (D_S(σ) still rising at σ = 10⁶), v0.1's D_S(σ) curves
   turn over inside the σ ≤ 10¹⁰ grid at *all* β. The peak measure
   is meaningful again.

3. **Charge conservation is exact** (Q_global = 0 at every record)
   and ±vertex-count balance holds to ~±10% per seed even though
   individual vertex charges drift. So the bookkeeping is sound.

**Interpretation.** We've traded one pathology (v2's runaway-D_S +
σ-saturation) for a different non-physical regime (homogeneous
small-world graphs at all β). Neither produces a clean D_S = 4
plateau. The charge dynamics are too aggressive — every interact
proposal has to compete with annihilate and pairCreate, which fire
~3× more often combined and don't carry any β-dependence in their
acceptance.

## Known v0.1 limitations

### Q drift under un-interact after annihilation

The frontier-summed `Q_global` is **exactly conserved** under the
forward-only moves (`interact`, `annihilate`, `pairCreate`) at
`cpBias = 0`. It is **not conserved** under `unInteract` when there
have been intervening annihilations.

The reason is a tension between the *classical-label* representation
of charge in v0.1 and the *historical* semantics of un-interact:

- When `interact(x, y)` runs, the worldline products `U_A, V_B`
  inherit their parent's charge, `chargeOf_[U_A] = chargeOf_[x]`.
- An `annihilate(U_A, m)` event can later change
  `chargeOf_[U_A]` without changing `chargeOf_[x]` (the parent on the
  past slice still has its original charge).
- When `unInteract` later removes the cell that created `U_A`, it
  restores `x` to the frontier with its still-original charge. But
  `U_A`'s charge (and `m`'s, if it survived) is now different from
  what it was at consumption time.

Net effect: `Q_frontier` after the un-interact can differ from
`Q_frontier` before, by the amount the annihilation neutralised.

**`feature_deactivate_on_annihilate` does NOT eliminate this drift.**
Deactivation cleanly removes the annihilated vertices from the
frontier, but the drift comes from un-interact restoring a parent
of *one side* of an annihilation event (e.g., x, the producer of
xp) while the partner side (m, paired with xp in the annihilation)
isn't accounted for — m was produced by a different cell that's
not being un-interacted. The conservation requires un-interact to
cascade through annihilation events to the partner's history, which
isn't implemented.

The covered regression tests
`testUnInteractCanDriftQWithAnnihilation` and
`testDeactivateOnAnnihilateDocumentedDrift` pin this behaviour
explicitly so it's stable until v0.2 changes it intentionally.

To eliminate the drift would require either:
- annihilation events become first-class objects in the un-interact
  cascade BFS (treat annihilation as a "fake cell" linking the two
  worldline-producing cells); or
- v0.2's qudit basis, where charge is intrinsic to the state and any
  modification (including annihilation) is propagated unitarily
  along the worldline.

## v0.2 sketch: 4-dim qudit vertices (Dirac-spinor style)

Vertices are no longer one-qubit but **one-ququart** (one qudit of
dim 4) with basis

```
{ |+, 0⟩, |+, 1⟩, |−, 0⟩, |−, 1⟩ }
```

The first label is the *charge sector* (matter / antimatter, the
particle-vs-antiparticle register); the second is the *spin /
occupation* (the existing qubit content). This is exactly the
component structure of a Dirac spinor at a spacetime point.

### What changes

- **State storage** per vertex becomes `Eigen::Matrix4cd`.
- **Charge becomes intrinsic**: the operator `Q̂ = diag(+1, +1, −1, −1)`
  acts on the 4-dim register; `⟨q⟩_v = Tr[ρ_v Q̂]` ∈ [−1, +1] is read
  out from the state.
- **The classical `chargeOf_` label is removed.** The continuous-charge
  feature of v0.1 emerges automatically from mixed-state 4-dim ρ.
- **Quantum charge superpositions** are now possible — a vertex can be
  in `(|+,0⟩ + |−,1⟩)/√2`, with ⟨q⟩ = 0 but *not* a classical mixture
  of `+` and `−`. The dynamics can then exhibit charge-interference
  effects.
- **C and CP are operators, not parameters.** Charge conjugation
  `Ĉ = X_charge ⊗ I_spin` (swap the charge register). CP-violation
  becomes "U doesn't commute with Ĉ ⊗ P̂ on the bipartite Hilbert
  space" — a clean operator statement.
- **Annihilation becomes a quantum amplitude**: project the joint
  state onto the charge-singlet subspace, weighted by amplitude.
- **`U` is now 16×16** acting on two qudits.

### Cost

- Per-vertex state: 4× larger (16 complex numbers vs 4).
- Per-joint state: 16× larger (256 complex numbers vs 16).
- Partial-trace / MI / matrix-multiply ops scale roughly as the
  dimension cubed → ~50–100× slower per interaction event.
- Implementation effort: a substantial refactor of
  `computeInteraction`, `partialTrace`, `traceOutFirst/Second`,
  `tensor2`, `jointMutualInformation`, plus all consumers. The bowtie
  topology and Regge machinery are unchanged.

### Decomposition of the 16×16 `U`

For SU(4) we had the magic-basis Cartan / KAK decomposition

```
U = (K₁ ⊗ K₂) · exp(i (c_x XX + c_y YY + c_z ZZ)) · (K₃ ⊗ K₄)
```

cleanly splitting "local frames" from "entangling core". **There is no
equally clean canonical decomposition for SU(16).** Options, in order
of usefulness:

- **Operator Schmidt decomposition (recommended).** Any operator
  `U: H_A ⊗ H_B → H_A ⊗ H_B` on a bipartite Hilbert space has a Schmidt
  decomposition
  ```
  U = Σ_k σ_k (A_k ⊗ B_k)
  ```
  with `{A_k}` and `{B_k}` orthonormal operator bases on each side
  (under the Hilbert-Schmidt inner product `⟨X, Y⟩ = Tr(X†Y)`) and
  σ_k ≥ 0. The *operator Schmidt rank* (count of non-zero σ_k) is 1
  iff `U = A ⊗ B` is purely local. Rank > 1 measures genuine
  entangling content; the σ-spectrum quantifies *how much*.
  Computationally: reshape `U_{ij,kl}` (with i,k indexing H_A and j,l
  indexing H_B) into a `d_A² × d_B²` matrix and SVD it — the singular
  values are the σ_k.
  This is the natural generalisation of the Cartan core
  `(c_x, c_y, c_z)` to higher dimensions. It loses the discrete
  "local left + local right" rotation labelling but preserves the
  "local content vs entangling content" split that we actually use.
- **Khaneja–Glaser recursive Cartan.** Recursively applies KAK to
  nested subspaces of SU(2^n). For two ququarts (n=4 qubits) it gives
  a depth-O(n) decomposition into local + Cartan-core layers, with
  many parameters but a definite tree structure. Useful if we ever
  need to *generate* a Haar-random U with explicit local/entangling
  structure.
- **Quantum Shannon decomposition.** Compiles any unitary into a
  sequence of single-qubit rotations and CNOTs (or any universal gate
  set). Standard in quantum circuit compilation. Doesn't give a
  "local + entangling core" split — gives a circuit.
- **Naked SVD on U as a 16×16 matrix.** `U = X · Σ · Y†` with Σ = I
  (since U is unitary, all singular values are 1). **Loses
  everything we care about** — it's a trivial reformulation. SVD only
  becomes useful when applied to the *operator-Schmidt reshape* above.

### Σ_AB as Choi state of U

The Choi–Jamiolkowski isomorphism gives us a principled state to put
on the entangling-core vertex Σ_AB, rather than the ad-hoc proxy used
in v0.1. For a 4-dim × 4-dim unitary `U`, the Choi state
`J(U) = (U ⊗ I)|Ω⟩⟨Ω|(U† ⊗ I)` is a pure state on a 256-dim doubled
Hilbert space, and its bipartite Schmidt decomposition has exactly the
same coefficients as the operator Schmidt decomposition of `U`. The
Choi state literally *is* the canonical "entangling content of U" as a
quantum state — the proper generalisation of the SU(4) Cartan core.

This raises the dimension-mismatch question: Σ_AB carries up to a
256-dim state while worldline vertices (U_A, V_B and ordinary
ququarts) carry 4-dim states. How does the heterogeneous interaction
work?

Three coherent options:

**(A) Reduce-before-interaction** *(v0.2 default).* When a 4-dim
worldline vertex interacts with a higher-dim Σ-vertex, *project* the
Σ-state onto a measurement basis matching the worldline's structure
(e.g., its charge-eigenbasis), giving a 4-dim collapsed state. Then
apply the standard 16×16 `U`. The Σ_AB vertex's full Choi state is
used at the moment of bowtie creation for principled per-edge MI
calculations, but is collapsed to 4-dim on subsequent interaction.
Physical analog: Compton scattering / decoherence at the interaction
vertex. The worldline acts as a measurement device on the photon-like
Σ; only the part of Σ aligned with the worldline's structure
participates.

**(B) Promote-to-higher-dim** *(deferred — too expensive at our
scale).* Lift the 4-dim worldline state to the 256-dim space via
`ρ_4 ⊗ (I_64 / 64)`, then apply a 65536×65536 `U` on the full joint
and extract marginals. Preserves all Choi content, but costs scale by
~10⁴×. Honest but probably untenable for research-scale runs.

**(C) Inert Σ_AB** *(deferred — drops a dynamics channel).* Σ_AB
carries full Choi at creation and is *never eligible* for further
interactions. It participates in the spectral-graph topology and
contributes to per-edge MIs forever, but does not get consumed as an
input to a future interact. Physical analog: virtual photon /
ephemeral mediator. Loses Σ-Σ scattering (the photon-photon analog).

(A) is the v0.2 default. (B) and (C) are kept as variants worth
playing with — (B) gives the gold-standard treatment if compute is
cheap enough, (C) gives the cleanest "interaction-quantum-as-frozen-
record" reading.

### Cluster-homogeneity-ranked charge observable

The v0.1 `getModuleCharges` observable returns net charge per
community-detected module of the MI-weighted graph. For testing the
inhomogeneous-baryogenesis hypothesis we need a sharper view: rank
clusters by their **charge homogeneity / purity** and read off the
CP-violation signature from the most-pure modules.

Concretely:

- For each detected module `M`, compute the **charge purity**
  ```
  P(M) = |Σ_{v ∈ M} q_v| / Σ_{v ∈ M} |q_v|
  ```
  bounded in `[0, 1]`: `P = 0` means perfectly balanced, `P = 1` means
  every charged vertex has the same sign. This is the natural
  "matter-dominance ratio" of a region.

- Sort modules by `P` descending. The top-`k` modules are the
  "most-pure" matter- or antimatter-dominated regions.

- Report:
  - The fraction of total volume in high-purity modules (the
    "domain-wall fraction").
  - The mean signed charge of the top-`k` modules (does the
    matter-dominance bias replicate at the *cluster* level even
    when global Q ≈ 0?).
  - The size distribution of charge-pure modules (does the geometry
    select a few large pure clusters, or many small ones?).

If the dynamics genuinely produces inhomogeneous baryogenesis from
near-zero ε_CP, we'd expect to see a small number of large
high-purity modules — i.e., the universe naturally separates into
matter-dominated and antimatter-dominated regions even with C/CP
near-symmetry. Reproducing the observed-universe asymmetry would mean
identifying one such pure cluster and treating *its* perspective as
the "observable universe".

This generalises straightforwardly to v0.2's continuous charges
(charges in `[-1, +1]` from the qudit-state read-out via `Q̂`) — the
purity formula `|Σ q| / Σ |q|` is well-defined for any charge values.

### Practical plan for v0.2

We don't need a fully general U-parameterisation for the experiment.
The pragmatic path is:

1. **Pick a fixed canonical 16×16 `U`** built from a parameterised
   Hamiltonian on the bipartite ququart system, e.g., a "Dirac-pair
   Hamiltonian":
   ```
   H = J · (Q̂_A · Q̂_B)        ← charge-charge coupling
       + α · (σ_A · σ_B)         ← spin-spin coupling
       + β · (Ĉ_A ⊗ Ĉ_B + h.c.)  ← charge-conjugation coupling
   ```
   with `J, α, β` configurable. Exponentiate to get `U = exp(−i H δt)`.
2. **Compute the operator Schmidt decomposition of `U`** once at
   construction time; report the σ-spectrum as a diagnostic (how
   entangling is this U?).
3. **Compute and store `J(U)` once** at construction time — pure
   256-dim state encoding U's full entangling content.
4. **Apply `U` as a black-box 16×16 multiply** on 4-dim × 4-dim joint
   states during ordinary worldline-worldline interactions.
5. **For Σ_AB-worldline interactions:** project Σ_AB's state onto its
   charge-eigenbasis (4-dim collapse), then apply `U` as above.
6. **Read out charge expectation values** from each vertex's ρ_v via
   `Tr[ρ_v Q̂]` whenever the move set needs charges (eligibility,
   annihilation matching, pair-creation distribution).

This sidesteps the SU(16) decomposition problem entirely — we use a
*chosen* `U`, not a *decomposed* arbitrary `U`. The Cartan core's
analog (the entangling content) is read out via the operator Schmidt
decomposition / Choi state as a one-time diagnostic at construction.
